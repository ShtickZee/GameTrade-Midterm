# Task: Add Authentication Entry Flow Without Recreating the Existing Landing Page

You are continuing an existing SwiftUI project for an iOS app called **Game Trade**.

The project already has an existing landing/onboarding page that introduces Game Trade.  
Do **not** recreate that landing page from scratch. Reuse the existing landing view exactly as it is.

Your job is to add the authentication entry flow.

---

## Required User Flow

### First-time user flow

1. User opens the app for the first time.
2. User sees the **Login / Sign In** screen.
3. User can tap:
   - **Don’t have an account yet?**
   - **Create an account**
4. Tapping **Create an account** navigates to the **Create Account** screen.
5. After successfully creating an account, the user is taken to the **existing landing page**.
6. The existing landing page should remain unchanged except for any minimal wiring needed to continue from it.

### Returning user flow

- If the user is already authenticated and has already completed onboarding, skip the landing page and go directly to the app’s main/home screen.
- If no main/home screen exists yet, show a temporary placeholder home screen.

---

## Important Constraints

- Do **not** create a new landing page.
- Do **not** redesign the existing landing page.
- Do **not** add a database yet.
- Do **not** add Firebase, SwiftData, Core Data, or any persistence database in this task.
- Use temporary in-memory mock authentication and `UserDefaults` only for session/onboarding state.
- Follow MVC.
- Keep the code compiling.
- Do not refactor unrelated parts of the app.

---

## Screen Requirements

### 1. Login / Sign In Screen

Create a standard, clean login screen similar to common Google-style authentication screens.

Layout requirements:

- App logo/icon centered near the top.
  - For now, use an SF Symbol controller icon:
    - `gamecontroller.fill`
- App title below the logo:
  - `Game Trade`
- Email input field.
- Password input field.
- Sign In button.
- Error message area.
- Bottom text:
  - `Don't have an account yet?`
  - Highlighted tappable text:
    - `Create an account`

Behavior:

- Disable Sign In unless email and password are valid.
- Minimum password length: 6 characters.
- On successful sign-in:
  - If this is a returning user, go to the main/home screen.
  - If onboarding has not been completed, show the existing landing page.
- Show errors inline, not with alerts if possible.

Treat “Login” and “Sign In” as the same screen. Do not create two separate screens for login and sign in.

---

### 2. Create Account Screen

Create a simple account creation screen.

Layout requirements:

- Same controller logo centered near the top.
- Title:
  - `Create Account`
- Email field.
- Password field.
- Confirm password field.
- Create Account button.
- Error message area.
- Optional bottom text:
  - `Already have an account? Sign in`

Behavior:

- Validate that:
  - Email is not empty.
  - Password is at least 6 characters.
  - Password and confirm password match.
- On successful account creation:
  - Mark the user as authenticated.
  - Mark onboarding as not completed.
  - Navigate to the existing landing page.

---
